# Phase 2: Feel, Look, and Champions — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the Phase 1 placeholder fight into something that reads like the reference rendition (`docs/reference/rendition.jpg`): a lit, layered dungeon stage with a camera; rigged, animated characters (Carl, Katia, Goblin Scavenger, Hobgoblin Brute); punchy hit feel; the rendition's HUD and on-screen buttons alongside the MCoC gestures; per-move sound and an announcer; tuned combat with crit/armor/parry lockout; and an S3 cinematic.

**Architecture:** The deterministic sim (`Fight`/`Fighter`/`AI`) stays untouched except for tuning data and a few read-only fields it exposes (camera target, hitstop per move, FX queue). All presentation grows in three new files: `65_stage.js` (parallax dungeon + camera), `68_rig.js` (bone rig, poses, tweening, per-character looks), `72_fx.js` (particles, popups, shake, slow-mo). `70_render.js` becomes the compositor: stage → reflections → fighters via rig → FX → HUD. `Fight` emits everything the presentation needs through the existing `onEvent` plus a per-frame `fx` list that `G` drains into `FX`; `Render` never mutates the sim.

**Tech Stack:** Same as Phase 1. Canvas 2D only. No assets required; an optional sprite-atlas hook is reserved for Phase 5.

**Spec:** `docs/superpowers/plans/2026-09-21-carls-arena-fighter.md` "## Spec" section, amended by the rulings below.

## Rulings that amend the spec (made 2026-09-21 from the rendition)

1. **Visual target is the rendition, executed as stylized vector-rig art, not photoreal and not pixel art.** Photoreal sprites are impossible without external assets; rigged 2D characters with shaded shapes and keyframe animation are achievable, animate from data, and scale to many characters. The Phase 1 outline's "procedural pixel sprites" is replaced by this.
2. **Assets are optional, not forbidden.** "Zero external assets" becomes "the game must run with zero external assets"; Phase 5 adds an optional atlas loader under `assets/` so hand-made or generated sprite sheets can replace a rig per character.
3. **Controls: gestures and buttons both.** Keep the MCoC tap/swipe/hold field gestures; add the rendition's on-screen buttons: BLOCK (hold) bottom-left, PUNCH (light), KICK (medium), POWER (fires the highest special the power bar affords) bottom-right. The S1/S2/S3 buttons from Phase 1 are replaced by POWER plus a long-press picker on POWER (hold ≥ 400 ms shows S1/S2/S3 chips, release on one fires it).
4. **Opponents are dungeon mobs first, champions second.** Phase 2 adds two mobs (Goblin Scavenger, Hobgoblin Brute) and one playable champion (Katia). Donut and Mongo (non-humanoid rigs) move to Phase 3.
5. **Encounters carry a floor.** `G.startFight({encounter})` accepts `{floor:1, name:'THE DEPTHS', enemy:'goblin', tier:'basic'}` and the HUD shows `FLOOR n • NAME` under the title, as in the rendition. Phase 3/4 builds the floor progression on top.
6. **Parry lockout** (from the Phase 1 final review): a block press that does not parry within `PARRY_WINDOW` frames arms a lockout; releasing and re-pressing block within `PARRY_LOCKOUT` frames cannot parry (it still blocks). This closes the mash-block exploit.

## Global Constraints

- Everything in the Phase 1 plan's Global Constraints still applies: single `index.html` from `tools/build.py`, `file://` runnable, 854x480 landscape, `STEP=1/60`, no `Math.random`/`performance.now` in `Fight`/`Fighter`/`AI`/`Ctrl.*`, Playwright-only dev dependency, save key `carlsArena.v1`, exact Fable 5.1 trailer on every commit.
- Before every commit: `python3 tools/build.py && python3 tests/harness.py --unit && python3 tests/harness.py --sim --seconds 60` exit 0. All 32 existing tests keep passing except where a task explicitly amends an assertion (only Task 2.6 does, for hitstop and parry).
- `Render`, `Stage`, `Rig`, `FX` never write to `Fight`, `Fighter`, or `AI` state. `Fight` never references `document`, `canvas`, `Audio`, `Render`, `FX`, or `Stage`.
- Performance: a full frame (`stepFrame` + `Render.frame`) must average under 6 ms in headless Chromium on this Mac, measured by the new harness `--perf` flag (Task 2.9).
- Determinism: any presentation randomness (spark directions, torch flicker) uses its own `RNG(seedFromFrame)` or a wall-clock-free counter, never `Math.random`, so screenshots are reproducible in `--sim`.
- Reference image for reviewers: `docs/reference/rendition.jpg` (untracked, local only). Screenshot comparisons are judged by a reviewer, not pixel-matched.
